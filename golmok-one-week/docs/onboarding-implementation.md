# 온보딩 프론트 구현

2026-09-19 · Figma ui 파일의 Onboarding1~4 적용.

## 메인 화면 (2026-09-19)

- Figma main 프레임(30:118)을 /report/[reportId]에 적용했다.
- 카드의 처방은 리포트 topActions 최대 4건을 사용하며, 카드의 근거보기와 전체 리포트 보기를 제공한다.
- Figma의 매출액·매출 증감률 숫자는 구현하지 않는다. 매출 데이터 연결 전 안내로 대체했다.
  이 서비스는 매출을 예측하거나 증감률을 단정하지 않는다는 제품 원칙을 따른다.
- 하단 챗봇 탭은 기존 리포트 챗봇을 열며, 처방 이력·알림·매출 데이터 연결은 준비 중 안내다.
- 원본 아이콘은 frontend/public/main/에 저장했다.

## 화면 흐름

`/` → `/search` → `/store/[storeId]/confirm` → `/store/[storeId]/connect`
→ `/report/[reportId]/area` → 기존 리포트.

- 검색은 Enter 또는 검색 아이콘으로 실행한다. 검색 결과 중 하나를 선택한 뒤 다음 단계로 간다.
- 결과가 없거나 검색에 실패하면 주소 직접 입력을 제공한다.
- 대표 메뉴는 하나다. 떡볶이·튀김·순대 칩은 입력 예시이며 누르면 입력값을 교체한다.
- 입력 옆 등록 버튼·Enter는 값을 확정하고 키보드를 닫는다. 자동 분류는 입력 후 400ms 뒤 요청한다.
- 분류 완료 또는 카테고리 직접 선택 후 다음 단계로 간다. 직접 선택한 카테고리는 늦게 도착한 자동 분류가 덮어쓰지 않는다.
- connect 화면의 하단 다음 버튼은 없다. 바로 시작하기에서 기존 createReport API를 호출한다.
- POS 연결은 준비 중 안내만 펼친다. 실제 인증·연동·매출 수집은 하지 않으며 공공데이터 분석으로 계속할 수 있다.
- 분석 중에는 중복 요청을 막고, 4xx 오류는 메시지와 재시도를 제공한다. 기존 네트워크·5xx 데모 폴백은 유지한다.

## 코드와 상태

- 공통 레이아웃·아이콘: frontend/components/onboarding/OnboardingShell.tsx.
- 온보딩 스타일: 같은 폴더의 onboarding.module.css. 공통 헤더·푸터는 AppChrome에서 온보딩 경로에만 제외한다.
- frontend/lib/onboarding.ts는 Zod로 검증한 세션 상태를 보관한다. 검색어·선택 가게·대표 메뉴·카테고리를 새로고침/뒤로가기 시 복원한다.
- 저장소가 차단된 환경에서도 메모리 상태로 진행한다. 이 경우 새로고침 복원은 보장하지 않는다.
- 백엔드 API와 공용 타입의 시그니처 변경은 없다. lib/api.ts와 lib/mock.ts에는 데모 전환 시 가게 정체성과 방금 생성한 리포트를 보존하는 캐시를 추가했다.

## 반응형과 에셋

- 844px 고정 높이를 사용하지 않는다. 100dvh를 기본으로 실제 VisualViewport 높이·상단 위치를 반영한다.
- 상단 진행 표시와 하단 버튼 사이의 본문만 스크롤한다. 가시 높이가 650px 미만이면 상단 여백을 줄인다.
- 키보드 표시·화면 회전·뷰포트 스크롤 시 크기를 갱신하고, 포커스된 입력창을 보이는 영역으로 이동한다.
- 최소 44px 터치 영역, 16px 이상 입력 글자, safe-area 여백, 키보드 포커스·상태 안내를 적용했다.
- 원본 Figma PNG/SVG는 frontend/public/onboarding에 저장한다. 임시 Figma URL을 런타임에 사용하지 않는다.
- Noto Sans KR은 Google Fonts 원본에서 한글 전체·기본 라틴·문장부호를 보존해 WOFF로 변환했다(약 1.87MB).
  나머지 문자는 시스템 글꼴로 표시한다. SIL OFL 라이선스는 같은 폴더의 OFL.txt에 포함한다.
- 디자인에서 작은 회색 글자 색상은 가독성을 위해 조금 진하게 적용했다. 30~36px 버튼은 터치 영역을 44px 이상으로 넓혔다.

## 검증 기록

- `npm run build`, `npx tsc --noEmit`, `npm run lint`, `git diff --check` 통과.
- 지연 응답 테스트: 이전 검색 결과가 최신 검색 결과를 덮어쓰지 않고, 자동 분류 응답이 수동 카테고리 선택을 덮어쓰지 않음.

- 실제 Spring Boot: 검색 200(20건), 메뉴 분류 200, 리포트 생성 201, 생활권 화면 진입 확인.
- 백엔드 중단 및 네트워크 차단: 검색·메뉴 선택·분석·리포트 전체 흐름, 데모 배지 확인.
- 메뉴 칩 선택/교체, 직접 입력, 카테고리 수동 변경, 새로고침 복원, 잘못된 단계 접근 복귀 확인.
- 주소 직접 입력 데모가 다른 가게로 바뀌지 않고 분석 결과 및 새로고침까지 유지되는지 확인.
- POS 준비 중 안내, 하단 다음 버튼 부재, 분석 400 오류 표시 및 재시도 성공 확인.
- 네 화면 모두 360px에서 가로 넘침 없음. 메뉴 화면은 390px·가로 모드 844px·데스크톱 1280px도 확인.
- 360×360 및 VisualViewport 높이 330px/offsetTop 20px 모의 환경에서 입력과 하단 버튼이 가시 영역에 남는지 확인.
- 실제 iOS Safari/Android 기기의 가상 키보드는 아직 검증하지 않았다. 모바일 기기에서 키보드 열림·닫힘과 회전 검증이 추가로 필요하다.
- 백엔드 검증은 날씨·명절 Provider를 mock으로 지정해 수행했다. 공공데이터 외부 API의 최신성 검증은 이번 프론트 작업 범위가 아니다.
