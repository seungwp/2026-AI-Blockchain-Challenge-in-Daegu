## 갱신 방법

저장소 루트에서 다음 명령을 실행한다. Python 표준 라이브러리만 사용한다.

```powershell
py -X utf8 golmok-one-week/scripts/collect_public_data.py --collect all
# 부분 갱신: --collect shops / --collect festivals / --collect prices
```

루트 `.env` 항목:

```dotenv
DATA_GO_KR_KEY=
KAMIS_CERT_KEY=
KAMIS_CERT_ID=
NAVER_MAP_CLIENT_ID=
NAVER_MAP_CLIENT_SECRET=
# 선택: SBIZ_API_KEY=별도 상가정보 키
```

키를 프론트 환경변수에 넣지 않는다. 수집기는 네이버 지도 API를 제외한 스냅샷을
`backend/src/main/resources/data/{store_enrichment,festival_details,ingredient_history}.json`에 저장한다.
데이터별 수집 성공 후 파일을 교체하며 실패 시 해당 기존 파일을 유지하고 종료 코드 1을 반환한다.
행사 상세 조회 일부 실패 시 상세는 비워두고 `detailAvailable=false`를 저장한다.
행사 사진/설명문 원문은 저장하지 않고 운영에 필요한 사실 필드만 저장한다.
원본 상가 전체·API 키·업소 관리번호는 저장하지 않는다.

**스냅샷 갱신 후 개발용 H2 백엔드를 재시작해야 적용된다.** 자동 예약 수집은 아직 없다.
기존 MySQL 데이터가 있는 환경은 `DataSeeder`가 재적재하지 않으므로 별도 갱신 작업이 필요하다.
KAMIS는 스냅샷 수집 당일에는 파일을 사용하고 이후에는 실 API를 조회한다.
실시간 결과는 품목별 6시간 캐시, 실패는 60초 캐시하며 실패 시 저장된 기준일의 가격으로 대체한다.

화면 근거보기는 데이터 성격을 `실시간 조회`(리포트 생성 시 API 응답), `저장 데이터`(검증 후 수집한
스냅샷), `예시 데이터`로 구분해 표시한다. KAMIS 품목은 API 성공·스냅샷 폴백 여부를 품목별로 표시하며,
행사·상권은 자동 수집 전까지 저장 데이터로 표시한다.

## 연결·계산 규칙

- 상가정보는 정규화한 상호와 건물 도로명주소가 일치하고 기존 좌표에서 100m 이내인 유일 후보만 연결한다.
  하나의 상가가 인허가 여러 행과 대응하면 전부 보류한다. 신규 점포를 합쳐 넣지 않아 이중 집계를 피한다.
- 기존 인허가 업태와 좌표를 보존하고 세부 업종 코드·명칭·기준월을 별도 보관한다.
  대상 가게의 세부 업종이 있으면 확인된 주변 점포끼리 비교한다. 미분류가 있으면 유사 업종 기반 처방을 만들지 않는다.
  미보강 대상은 기존 인허가 업태 기준 비교를 유지한다. 직접 입력한 임시 가게는 주변 집계에서 제외한다.
- 권고와 상권 결과에 상가정보 출처 15를 연결한다. KAMIS 출처 14의 제공기관을 한국농수산식품유통공사로 정정했다.
- 가격은 동일 품목·지역·거래단계의 평균값을 사용한다. 7일 전 관측이 없으면 그보다 최대 3일 앞선 값을 비교하고 실제 비교일을 표시한다.
  결측·0·비정상 가격과 개별 시장 행은 평균 가격으로 사용하지 않는다. 최신 실측일보다 뒤의 평년 행은 최신 실측 가격을 없애지 않는다.
- 기존 가격 CSV의 9/13 모델 결과는 재학습하지 않았다. 예측 기준일이 오늘보다 2일 이상 오래되면
  `probSpike=null`, `alert=false`, `predictionStale=true`로 보내고 갱신 대기를 표시한다.
  가격 기준일·예측 기준일을 분리하며 과거 모델을 최신 예측으로 재포장하지 않는다.
- 행사 상세는 기존 3km 필터에 함께 전달한다. 방문객 수·매출 변화는 추정하지 않는다.
- 주소 검색은 네이버 Maps Geocoding의 도로명·건물번호가 특정되는 대구 주소만 사용한다. 후보가 여러 개면 400과 안내 문구를 반환한다.
  확인된 WGS84 좌표를 직접 입력 가게에 저장하며, 임의 좌표나 기존 가게 좌표를 재사용하지 않는다.
- API 4xx는 데모 성공으로 바꾸지 않는다. 네트워크·서버 장애의 데모 폴백은 유지한다.
  리포트 생성은 최대 60초, 챗봇은 45초 대기한다.

## 프론트 인수인계

기존 페이지 구조와 스타일은 유지했다. 식자재·행사 컴포넌트에 새 사실 항목을 추가하고
주소 등록 실패 이유와 네이버 지오코딩 기반 위치 분석을 보강했다. 타입의 새 필드는 optional이므로 기존 데모·저장 리포트와 호환된다.
가격 이력은 `<details>`를 열어 확인할 수 있다. 새 화면 디자인이나 인증·유동인구 연동은 포함하지 않는다.

## 검증

- 백엔드: `gradlew.bat test`. 기존 build 폴더가 IDE에 잠기면 별도 buildDirectory에서 실행.
- 프론트: `npm run build`.
- 실제 연결: 9091 포트 백엔드 실행 후 루트에서 `py -X utf8 golmok-one-week/scripts/check_public_data.py`.
  주소 검색·Swagger·식자재 이력·출처·리포트 재조회·좌표 없는 가게를 검증한다.
- 수집 스크립트와 스냅샷에는 인증정보를 저장하지 않는다. KAMIS 응답이 인증정보를 돌려주는
  `condition` 항목은 진단 출력에서도 제거한다.
