S. 매출 데이터 (가상 데이터로 생성)
----------------------------------------------------------------
 결정: 실제 가게 매출은 공공데이터에 없으므로 가상(합성) 데이터로 시연.

 [가상 매출 데이터에 넣을 항목]
  - 가게ID, 업종(한식/치킨/카페 등), 행정동, 좌표
  - 날짜, 시간대(점심/저녁/심야), 요일
  - 채널별 매출: 홀 / 포장 / 배달
  - 주문 건수, 객단가
  - 메뉴(대분류)별 판매량
  - 식자재 원가(주요 품목별 사용량 x 단가)

 [가상 매출을 만들 때 반영할 공공데이터 요인]  ← 아래 A~E 데이터와 연결
  - 날씨: 비/폭염/한파 → 홀 감소, 배달 증가
  - 행사: 인근 축제·경기일 → 매출 증가 (거리에 따라 차등)
  - 공휴일·방학 → 업종·입지별 증감
  - 식자재 가격 → 원가율 변동
  - 주변 경쟁 개업 → 이후 몇 달간 매출 감소
  - 기본 패턴: 요일·계절성 + 무작위 잡음

 [주의]
  - 심사 때 "예측 정확도"는 실제 매출이 아니라 가상 데이터 기준임을 명시
  - 가상 데이터 생성 규칙(가정)을 제안서에 투명하게 적을 것
  - 참고할 실제 분포: 빅데이터활용센터 카드사·대구로 데이터(분석실 전용, 본선용),
    소상공인365 행정동 업종 평균매출(화면 조회)

공통 확인 기준 (데이터 찾을 때 체크)
----------------------------------------------------------------
 1. 대구 포함 여부   : 전국 데이터면 대구 지역 필터가 되는지
 2. 날짜 단위        : 일별이 가장 좋음 (월별이면 조언에 쓰기 약함)
 3. 위치 정보        : 주소 또는 좌표가 있어야 "우리 동네"로 좁힐 수 있음
 4. 과거 기간        : 가상 매출과 붙여 학습하려면 최소 2~3년
 5. 제공 방식        : API는 서비스용, 파일은 학습용
